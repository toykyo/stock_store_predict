
지금 단계에서는 수집 -> 저장 -> 가공 -> 학습 -> 예측 -> 검증 순서로 끊어서 가는 게 맞습니다. 한 번에 모델부터 들어가면 기준이 흔들립니다.

전체 순서

목표와 예측 단위를 확정
원천 데이터 스키마 확정
데이터 수집 파이프라인 구축
일별 스냅샷 적재 자동화
피처 테이블 설계 및 생성
타깃 정의 및 생성
EDA와 기초 상관/조건 분석
베이스라인 모델 학습
데일리 추론 파이프라인 구축
백테스트 및 성능 모니터링
UI/에이전트 연결
1. 목표와 예측 단위 확정
먼저 이걸 고정해야 합니다.

업종을 먼저 볼지, 종목까지 바로 갈지
예측 대상이 1일 후 상승여부인지 5일 후 초과수익인지
결과를 확률로 볼지 수익률로 볼지
KOSPI/KOSDAQ 전체를 다룰지 범위를 제한할지
추천 시작점:

1차 목표: 업종 5일 후 상승 여부, 업종 5일 후 시장 대비 초과수익 여부
2차 목표: 개별 종목 5일 후 업종 대비 초과수익 여부
2. 원천 데이터 스키마 확정
여기까지가 기반입니다.

필수 테이블:

stock_master
market_daily_factors
sector_daily_snapshot
stock_daily_snapshot
이 단계에서 확정할 것:

PK
날짜 기준
업종 코드 체계
시장 구분
결측치 처리 기준
수정주가 사용 여부
3. 데이터 수집 파이프라인 구축
수집 대상을 먼저 좁혀야 합니다.

수집 우선순위:

한국거래소 기준 업종/종목 기본정보
종목별 일별 OHLCV, 거래대금, 시총
업종별 구성 종목 일별 스냅샷
시장 변수
이벤트/캘린더 변수
이 단계 산출물:

데이터 소스 목록
각 소스별 수집 함수
날짜별 수집 가능 여부 확인
4. 일별 스냅샷 적재 자동화
매일 장 마감 후 한 번 돌아가는 구조를 만듭니다.1

배치 순서:

stock_master 갱신
market_daily_factors 적재
sector_daily_snapshot 적재
stock_daily_snapshot 적재
중복 체크 및 upsert
이 단계 목표:

특정 날짜를 넣으면 재수집 가능
당일 배치 실패 시 재실행 가능
로그 남기기

이벤트 플래그
최근 N일 상대강도
